# Доступы и чек-лист передачи

Этот документ перечисляет, **что передать**, но не содержит паролей и токенов.

## 1. Репозиторий и исходники

- [ ] Добавить нового разработчика в GitHub-репозиторий `steamxheat/DeepCurrent`.
- [ ] Передать ветку `main` и объяснить, что production сейчас на `06dc6d9`.
- [ ] Передать незакоммиченные `src/lib`, `scripts`, `docs` и `outputs` из локальной папки.
- [ ] Не добавлять 8.7 GB `backups/` обычным коммитом.
- [ ] Составить отдельный архив evidence либо дать read-only доступ к исходному диску.
- [ ] После копирования сравнить список и checksums важных файлов.

Рекомендуемые команды инвентаризации:

```bash
git status --short
git ls-files --others --exclude-standard
du -sh backups outputs
find docs/handoff -type f -maxdepth 1 -print
```

## 2. Сервер и Tailscale

- [ ] Добавить человека в нужный Tailscale tailnet либо выдать отдельное устройство/роль.
- [ ] Добавить его SSH public key; не передавать чужой private key.
- [ ] Проверить `ssh admin1337@mac-mini` через Tailscale.
- [ ] Показать `/home/admin1337/Services/DeepCurrent` и PM2.
- [ ] Показать shared router `/home/admin1337/shmotki/server/src/tailscale-router.mjs` и объяснить, что порт 8443 принадлежит другому проекту.
- [ ] Передать административный доступ к Tailscale Funnel отдельно, если он должен управлять публичной ссылкой.

Пароль от Mac/Ubuntu не нужен для обычной работы при правильно настроенных Tailscale и SSH-ключах. Если человеку нужен `sudo`, лучше выдать ему отдельную учётную запись/правило, а не сообщать общий пароль.

- [ ] Оценить свободное место: production DB около 37 GB.
- [ ] Создать новый консистентный `npm run backup:db`.
- [ ] Выполнить `PRAGMA quick_check`.
- [ ] Передать backup зашифрованно; это пользовательские настройки и операционная история.
- [ ] Не передавать случайную копию живой `.sqlite` без WAL/online backup.
- [ ] Проверить восстановление на отдельном пути до смены production.
- [ ] Назначить регулярное резервное копирование и retention.

## 8. Что не нужно передавать

- `node_modules/` и `.next/` локальной машины — они воспроизводятся через `npm ci` и `npm run build`.
- временные QA fixtures, если их доказательства уже сохранены и они не нужны для расследования;
- старые/отозванные токены;
- личный SSH private key;
- пароль владельца Mac/Ubuntu в сообщении или документе.

## 9. Приёмка передачи новым разработчиком

Новый человек должен самостоятельно показать:

- [ ] security-upgrade Next.js и отсутствие известных production audit findings;
- [ ] чистую установку и успешные test/lint/TypeScript/build;
- [ ] чтение production-статуса без изменений;
- [ ] понимание observed vs confirmed/exact;
- [ ] создание и проверку backup на отдельном пути;
- [ ] доступ к публичному и tailnet URL;
- [ ] знание, что автоматическая торговля и billing ещё не реализованы;
- [ ] знание, что полностью принятых трейдеров пока 0;
- [ ] план первого изменения с rollback и без удаления SQLite.

## 10. Завершение передачи

После успешной приёмки:

- удалить ненужные старые SSH keys и Tailscale devices;
- ротировать доступы, которые передавались временно;
- зафиксировать владельцев GitHub, Tailscale, Telegram, VAPID, data-provider и backups;
- записать дату, commit, build ID и checksum последнего проверенного backup.
