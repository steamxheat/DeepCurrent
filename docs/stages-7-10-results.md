# Этапы 7–10: локальная реализация и ограничения

13 октября 2026. Изменения не выкатили на production и не отправили в GitHub. Предыдущие изменения этапов 2–6 и PWA сохранены, база не сбрасывалась. Бюджет Hyperliquid остался 600 units/min; новая нода и платные источники не подключены.

## Профиль

- Открытие и длительность показываются только при согласованной позиции и доказанном покрытии истории. Неизвестные даты не заменяются временем снимка.
- Последнее изменение берётся из журнала; обновление снимка — отдельное время.
- Первый размер — первое доказанное исполнение Open/Flip, не выдуманный полный размер заявки. Текущий размер, USD notional, маржа, вход, Mark, P&L, ROI по марже, плечо и ликвидация доступны на карточке и в таблице.
- Монета, Long/Short, последнее действие, источник, подтверждённое открытие; сортировки времени, длительности, суммы USD, P&L, ROI и цены. Неизвестные открытия/ROI/длительности находятся в конце обоих направлений сортировки.
- Журнал профиля фильтруется на сервере по монете, действию, направлению и точности; пагинация по 50. На телефоне открытые и завершённые позиции представлены карточками.

## Лента

- Рыночный BUY/SELL не считается доказательством LONG/SHORT. Точное исполнение отделено от текущего состояния всей позиции.
- Биржевое время с секундами MSK, количество, цена, USD notional, источник, first receive и его задержка. Плечо неизвестно, если нет согласованного свежего снимка.
- Состояния: активная в свежем снимке, завершённая по журналу, отсутствующая в свежем снимке без установленного закрытия, неизвестная. Исторический Open не выдаётся за текущий вход. Для завершённой позиции показываются закрытие, известная длительность и результат после комиссий.
- Повторное открытие не меняет статус прошлого жизненного цикла. Обогащение заменяет строку с тем же ID, не создаёт второй fill.
- Все серверные фильтры применяются до сортировки и пагинации. Список монет содержит каталог, а не только последние 50 live-событий. Счётчики и CSV относятся к реально показанной странице.
- SSE инициирует объединённое обновление первой страницы; периодическая сверка статусов — каждые 10 секунд. Скрытая вкладка не запрашивает историю. Общий короткий кэш не выполняет один одинаковый DB-запрос на каждого зрителя.

## Совпадения

- Серверное окно: 1м, 5м, 15м, 1ч, 4ч, 24ч; старые настройки 30м/2ч сохранены для совместимости.
- Один адрес/рынок/жизненный цикл считается один раз; учитываются подтверждённые входы и увеличения. Flip учитывает только новый размер, не объём закрытия прежней стороны.
- Известные master/subaccount-связи берутся из публичного `subAccounts`, сохраняемого фоново не чаще раза в сутки для просматриваемых адресов. Сильная корреляция истории дополнительно объединяет источники.
- **Независимость владельцев не доказана.** Отсутствие найденной связи не делает два адреса гарантированно независимыми. В интерфейсе используется слово «источники», а не доказанное число разных людей.
- Видны все участники, исключённые связанные адреса, цена, размер, время, точный разброс в миллисекундах, изменение размера, Quality/Copyability и текущий статус.
- Минимум источников, Quality, Copyability, только проверенные активные позиции. Неизвестные scores не проходят ненулевой порог. Copyability остаётся моделью, не реальным backtest копирования.
- Применение по последним 20 000 событиям за сутки ограничено ради общей нагрузки; при усечении возвращается `capped` и интерфейс предупреждает. Это не полный блокчейн-индекс.

## Уведомления

- Серверная изоляция пользователей и избранного сохранена. Добавлены Open/Close, Long/Short, минимум/максимум плеча, Copyability, окно совпадений и минимум источников. Остались Add/Reduce, минимальный исполненный USD notional, монеты, тихие часы, Telegram, Web Push и inbox.
- Включённый фильтр плеча/Copyability не пропускает неизвестное значение. Порог Copyability использует свежую модель с достаточной confidence; на непросматриваемом адресе модель может отсутствовать и уведомление тогда не пройдёт этот фильтр.
- Quiet hours проверяются и в момент подготовки, и перед фактической отправкой; выключение канала/удаление избранного отменяет pending delivery. Сообщение старше пяти минут отменяется. Задержанное подтверждение может создать сигнал в течение двух минут после исполнения.
- Inbox уникален по user + group event ID. Outbox уникален по group + user + channel; для Push добавлен отдельный destination, чтобы не повторять успешную доставку другому устройству при частичном сбое.
- **Внешняя exactly-once доставка не гарантирована:** если Telegram/Push принял сообщение, а ответ потерялся, повтор после timeout может дать редкий дубль. Протокол провайдера не даёт общей транзакции с SQLite.
- Переворот является одним FLIP-сигналом: при отключении Open или Close он исключается целиком, не разбивается на две пользовательские доставки.
- Push endpoint ограничен поддерживаемыми провайдерами; произвольный HTTPS URL не может превратить сервер в прокси. Неподдерживаемую старую подписку нужно подключить заново через поддерживаемый браузер.

## Проверка

- `npm test`: 108 тестов, включая lifecycle/reopen/unknown/absent, серверную пагинацию, длительность/ROI, linked clusters, границы фильтров, тихие часы, изоляцию пользователей и независимые retry destinations. Push transport заменён mock-функцией: сбой устройства B не вызывает повторной отправки устройству A; сетевых сообщений этот тест не создаёт.
- Малые цены и комиссии не округляются в ложный ноль. Компактное относительное время использует переданный серверный clock на первом рендере, а не разные `Date.now()` при SSR и hydration.
- TypeScript, ESLint, production build, `git diff --check`.
- `node --experimental-strip-types scripts/check-stages-7-10.mjs`: 19 HTTP-проверок на **отдельной временной SQLite** и preview 3001. Никаких сообщений Telegram/Web Push, production БД и сервисы не меняются. `--keep` оставляет только тестовый preview с явно названными QA Wallet.
- На fixture: 1000 запросов журнала, 0 ошибок, локальный p95 около 21мс; 1000 SSE-соединений / 12с, 0 ошибок, первый ответ p95 328мс, server emit → client p95 54мс. Новые биржевые сделки в этом прогоне отсутствовали: эти цифры **не подтверждают скорость источника или exact-охват 1000 кошельков**.
- Browser: desktop 1365px и mobile 390px, без горизонтального переполнения страницы; фильтры, полный MSK timestamp, неизвестные значения, ссылки участников и настройки. Native iOS/Android/Telegram permission prompts не проверялись.
- Старый localhost dev process держал экземпляр журнала без `queryEvents`; локальный dev перезапущен, `/`, `/api/events`, `/api/confluences` отвечают 200. Это не production restart.

## Что остаётся до приёмки продукта

24–72ч shadow на реальном сервере, реальная доставка уведомлений с согласия пользователя, проверка актуальных данных всех адресов, native Telegram/PWA, нагрузка разных профилей, безопасный rollout и откат. История API ограничена, PostgreSQL/Redis ещё не внедрены, страницы истории могут меняться при позднем backfill. Полная локализация профиля остаётся отдельным незавершённым пунктом. Точные ≤3с для всех 1000 не достигнуты. Сейчас это проверенная локальная реализация, не акт готовности всего продукта.
