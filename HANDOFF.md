# Передача проекта Deep Current

Актуальность этого пакета: **2 ноября 2026 года, Europe/Moscow**.

Этот файл — точка входа для нового разработчика. Он отделяет подтверждённое текущее состояние от старых планов и промежуточных экспериментов.

## Что это за проект

Deep Current — Telegram Mini App / PWA для наблюдения за публичными криптотрейдерами. Текущая production-версия собирает публичные данные Hyperliquid, строит рейтинг и страницы кошельков, показывает позиции и исполнения, отправляет Telegram/Web Push уведомления и хранит журнал в SQLite.

Целевой продукт шире текущей версии: выбрать 10–20 действительно сильных и копируемых трейдеров, доставлять полное событие в интерфейс не позднее 5 секунд и затем безопасно добавить автоматическое копирование на пользовательские Bybit-аккаунты. **Автоматическая торговля, биллинг подписки и полностью принятая подборка трейдеров пока не реализованы.**

## Критически важное перед передачей

- GitHub: `https://github.com/steamxheat/DeepCurrent.git`, ветка `main`.
- Локальный и production `HEAD` на момент проверки: `06dc6d94fc6788260f8f5d3c84996e5c35b81947` (`06dc6d9`).
- Локальная рабочая папка содержит большой **незакоммиченный исследовательский слой**: новые скрипты/библиотеки отбора, 9 документов, `outputs/` и около 8.7 GB доказательств в `backups/`. Обычный `git clone` этого не получит.
- Production-код чистый относительно Git, кроме `backups/`. Production SQLite — около 37 GB плюс активный WAL; её нельзя копировать как обычный файл во время записи.
- **Security-блокер:** `next@16.4.0` попадает под две critical RCE и одну high DoS advisory. `npm audit` предлагает совместимое исправление `16.4.4`; до обновления и повторных проверок новый deploy делать нельзя.
- Секреты не находятся в этих документах. `.env.local`, токены, приватные VAPID-ключи и доступы передаются отдельно через защищённый канал.
- Старые `README.md` и `DEPLOY.md` полезны, но частично устарели. Для текущего production сначала использовать этот пакет.

## Главные правила для следующего разработчика

1. Не считать быстрый рыночный print доказанным Open/Close кошелька.
2. Не заменять неизвестное время, PnL, funding, просадку или полноту истории нулём или догадкой.
3. Не обещать абсолютные 5 секунд по одному p95 или короткому тесту.
4. Не включать реальные сделки и рассылки при исследовании источников.
5. Перед изменениями production сделать консистентный backup SQLite и сохранить предыдущую сборку.
6. На сервере должен оставаться ровно один web-процесс и один collector-процесс.
7. Не коммитить секреты, production SQLite и многогигабайтные evidence-файлы.

## С чего начать новому человеку

1. Получить GitHub, Tailscale/SSH и секреты по чек-листу.
2. Скопировать **всю текущую локальную папку исследования** либо сначала оформить её отдельным коммитом без `backups/`.
3. В отдельном worktree обновить Next.js security-патчем, затем запустить `npm ci`, `npm test`, `npm run lint`, `npx tsc --noEmit`, `npm run build`.
4. Через Tailscale проверить production, PM2 и свободное место, ничего не перезапуская.
5. Продолжить работу с раздела «Следующий план», не возобновляя старые массовые workers вслепую.
