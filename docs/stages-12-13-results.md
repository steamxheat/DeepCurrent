## Изменения

- Стартовый preview ленты — 100 событий вместо чтения/обогащения до 2000. Полная история не удаляется: серверная пагинация и фильтры остаются. Фильтр кошельков применяется до лимита.
- Evidence читает состояние по wallet+coin и coverage по wallet один раз на batch; завершённые сделки сгруппированы по монете. Сохранены правила exact/unknown/absent/closed.
- Добавлен индекс lifecycle(wallet,coin,time,id). Установка индекса на большую реальную БД может занять время; production-миграция не проверена.
- Одинаковые окна/пороги совпадений делят готовый результат в пределах существующего 10-секундного кэша; разные правила изолированы, максимум 100 вариантов. Короткая задержка этого кэша не выдаётся за биржевую realtime-задержку.
- Публичные `/api/events` и `/api/confluences` используют общий кэш сериализации и gzip, если клиент разрешает его. Участники и точность не урезаются. Персональные endpoints/сессии не используют этот helper; ответы остаются no-store, Vary=Accept-Encoding.
- Кэш начального SSE-снимка освежает evidence даже без новой ревизии fills, чтобы новое подключение не получало старый статус позиции бесконечно.

## Измерения локально

Это компьютер разработчика, не Mac mini. Тестовые данные — отдельная SQLite в системном temp, не production.

| Проверка | Результат |
|---|---|
| Ответ главной на сохранённых локальных данных | 2,499,637 → 619,491 байт, около −75%; dev-замеры, не гарантия production latency |
| Evidence 10 000 событий / 1000 кошельков | 163 → 49 мс в двух соседних прогонах; не статистический длительный benchmark |
| 1000 смешанных API-запросов, concurrency=50 | 0 ошибок; пять маршрутов, p95 примерно 188–266 мс в последнем прогоне |
| Большое совпадение с участниками | 658,350 байт JSON → 91,188 байт gzip; все данные сохранены |
| 1000 разных wallet/watch, concurrency=10 | 0 ошибок; p50 2.85 мс, p95 7.46 мс, max 25.6 мс |
| 1000 SSE, 12 секунд | 0 ошибок; первый ответ p95 265 мс; server emit → client p95 63 мс |

После отключения всей тысячи выполнено повторное подключение 1000 SSE / 6 секунд: 0 ошибок, первый ответ p95 337 мс. Это проверяет освобождение соединений в коротком сценарии, а не отсутствие утечек за несколько суток.

Нагрузочный preview содержит 1000 кошельков и 20,011 событий, в том числе позиционные снимки. Это синтетический dataset, не 1000 дополнительно проверенных трейдеров. SSE-прогон не содержит новых реальных fills: exchange-to-client latency отсутствует, не «0 мс».

За 12 секунд SSE передал ~41.8 МБ, включая начальные снимки. На заявленной исходящей скорости ~30.6 Мбит/с это уже существенная часть канала. Добавление API/страниц/новых сделок может превысить сеть. Поэтому эти результаты не сертифицируют комфорт 1000 production-пользователей. Полные страницы разных профилей и collector+web при одновременной записи ещё не нагружались на Mac mini.

## Повторение

```sh
npm test
npm run lint
npm run build
npm run benchmark:journal
node --experimental-strip-types scripts/check-stages-7-10.mjs --load --keep
```

Последняя команда печатает путь к отдельной fixture и держит localhost:3001; завершить Ctrl+C. В другом терминале:

```sh
node scripts/check-http-load.mjs http://localhost:3001 1000 50
node --experimental-strip-types scripts/check-realtime.mjs http://localhost:3001/api/live 1000 12000
node --experimental-strip-types scripts/check-profile-load.mjs http://localhost:3001 /точный/путь/из/вывода/fixture.sqlite
```

HTTP/profile bulk scripts ограничены localhost, profile script — временной fixture, без произвольной production-БД. Нагрузка останавливается при ошибке/слишком медленном ответе. Эти команды нельзя переносить на публичный адрес как «безопасный тест».
