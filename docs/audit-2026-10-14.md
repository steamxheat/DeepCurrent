# Data-path audit — 14 October 2026

What this repo does: Deep Current collects public Hyperliquid executions, reconstructs positions in SQLite, and serves a wallet dashboard, activity feed and personal notifications.

Scope: execution ingestion, confirmation queue, journal replay, completed positions, feed merging, notification eligibility, dependency audit and bounded production checks. This is not an independent review of every repository file or a 1,000-browser certification.

## Must fix

1. **A tiny trade could display the wrong exit price.** `stats.ts` divided by a minimum quantity of 1e-9; a 1e-10-unit close at $200 displayed $20. Use the actual nonzero exit quantity and exact decimal continuity instead of epsilon comparisons. Without this, price and duration reconstruction can be wrong. Fixed with tiny-close, tiny-gap and tiny-add fee regressions.
2. **Missing executions were removed before completed-position reconstruction.** `fill-journal.ts` skipped fills without a confirmed starting position and conflicted rows. This could join a close/reopen sequence into one apparently continuous trade and retain a false opening date. Preserve those rows as continuity breaks. Without this, a precise-looking date can describe the wrong position. Fixed; projection algorithm 6 rebuilds derived records from retained raw observations.
3. **The live buffer could retain a rejected OPEN.** `live.ts` preferred an older exact row over a later server correction downgraded to observed/unknown. Accept authoritative position-status corrections; do not accept an unannotated market echo as proof. Without this, the UI can still show an opening the journal no longer confirms. Fixed with both correction and raw-echo regressions.
4. **Expired confirmations could disappear without recovery.** `confirmation-queue.ts` removed expired windows or trimmed their beginning without scheduling history recovery. Queue the affected wallet for recovery and log the missed interval. Without this, counters show a failure but the execution may never be recovered. Fixed with expiry and trimming tests.
5. **An entry notification could be sent without proof the position is still open.** `notifications.ts` rejected closed/absent but permitted unknown or missing status. Require open status for OPEN/ADD/FLIP. Without this, a historical or unconfirmed entry can become a misleading notification. Fixed with eligibility tests; automatic delivery remains disabled in shadow mode.
6. **A large watch list could crash gap recording.** `markStreamGap` rejected more than 5,000 addresses. Validate the complete list first, then update in bounded transactions. Without this, connection recovery can fail as user favorites grow. Fixed with a >5,000-address regression; this does not prove collection capacity for that many addresses.

## Should fix

7. **Free-source confirmation latency remains variable.** Production diagnostics showed fast observed fills but confirmation queues can wait tens of seconds or more under shared API limits. Keep execution time, receipt time and confirmation state separate; measure percentile latency and prioritize viewed/favorite wallets. Without an adequate complete source, exact Open/Close within three seconds for all 1,000 wallets cannot be promised. No paid infrastructure or node added.
8. **The development dependency tree has an unpatched advisory.** Five high audit entries trace to braces through micromatch/fast-glob and Next's lint tooling; production-only audit reported zero. The [upstream advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) lists no patched release. Do not force-downgrade Next lint configuration to v14; avoid untrusted glob patterns and track the upstream fix. Without this, untrusted recursive patterns can exhaust lint-tool resources. Dependency changes deferred because no safe patched version was available.

## Acceptance limitations

Physical iPhone installation and actual Web Push delivery require a real device subscription and are not certified by API/cryptographic checks. Continuous 24–72-hour observation and 1,000 simultaneous complete browsers are not replaced by a bounded load check. Unknown historical opening dates remain unknown rather than fabricated.

Verdict: reproduced correctness defects have targeted fixes and regression coverage; do not describe this as fully audited, zero-risk or three-second exact coverage of all wallets. Verification and deployment results are recorded below when complete.
